# tsidp -> Pocket ID

Status: **planned, not applied** (written 2026-10-28; Phase 1 policy edited in the working tree on 2026-10-29, Phase 2 manifests drafted but not wired in). Nothing here is in the cluster yet; `platform/tsidp` is still the live IdP.

This replaces the tailnet identity provider at `idp.beaver-cloud.ts.net` with [Pocket ID](https://pocket-id.org): passkeys instead of Tailscale `WhoIs`, admin-registered OIDC clients instead of dynamic client registration. The hostname stays, so app configs, the CoreDNS rewrite, the egress `ExternalName` Service and the gatus canary all stay.

Two things change at once on purpose, because both force the same one-time login outage and the same app-account touch:

1. the IdP itself, and
2. the account address (`kevindurb@github.idp.beaver-cloud.ts.net` -> `kevindurb@fastmail.com`).

## Why

| | tsidp | Pocket ID |
| --- | --- | --- |
| Identity | Tailscale node identity (`WhoIs` on the browser connection) | Passkeys stored by Pocket ID |
| Tagged sources | `/authorize` rejects them, so `tag:dev` and LAN clients behind `tag:router` / `tag:travel-router` could never log in | Work normally |
| Client registration | DCR, clients appeared at runtime | Admin/API-created; ID can be chosen, secret is supplied or generated |
| Per-app authorisation | ACL caps (but `/authorize` never consults them) | User groups per client |
| Account address | `kevindurb@github.idp.beaver-cloud.ts.net` (synthesised as `<login>@<tsidp host>`) | A real mailbox, so login codes can be emailed |
| State | 1Gi PVC (signing key, DCR clients) + a tailnet device | 1Gi PVC (SQLite, uploads), reachable only through the ingress proxy |

tsidp is not coming back: its PVC holds the signing key and DCR clients, and its tailnet device needs an interactive tsnet login to re-register. Treat this as one-way.

## Decisions

- **Hostname stays `idp.beaver-cloud.ts.net`.** Immich's issuer URL, the CoreDNS rewrite and the egress Service are untouched; only credentials and endpoint paths change. Cost: the old `idp` device must be deleted before the VIPService can take the name.
- **`tag:tsidp` -> `tag:idp`.** The policy is being edited anyway; a tag named after a dead product is worse than one apply.
- **Human-readable client IDs** (`linkding`, `miniflux`, `romm`, `donetick`, `semaphore`, `immich`), secrets generated by a one-off script and sealed. No DCR, no reconciling Job.
- **Login codes via `platform/smtp-relay`**, admin-initiated only.
- **`UI_CONFIG_DISABLED=true`**: Pocket ID's application configuration lives in the manifest, not in its SQLite DB.
- **Account address becomes `kevindurb@fastmail.com`** (already the Alertmanager recipient, so the mailbox is live).

## Target request paths

```
browser ── tailnet ──> idp VIPService (tag:idp, ingress-proxy-group) ──> pocket-id Service:80 -> pod:1411
app pod ── CoreDNS rewrite ──> idp.tailscale.svc.cluster.local (ExternalName)
        ── oidc-egress pods (tag:k8s-oidc) ── tailnet ──> idp VIPService
gatus   ── same egress path (canary)
```

## Phase 1 - Tailscale policy prerequisites

Land first: the Ingress/VIPService is unapproved and untaggable until these exist.

`tailscale/policy.hujson` (applied by `.github/workflows/tailscale.yml`; PRs run `action: test`):

1. `tagOwners`: replace `tag:tsidp` with

   ```json
   "tag:idp": ["group:admins", "tag:k8s-operator"],
   ```

   The operator **must** be an owner or it cannot apply the tag to the VIPService (same failure as `tag:travel-lab`, see `docs/tailscale-acl-hardening.md`).

2. `autoApprovers.services`: add `"tag:idp": ["tag:k8s"]`. Without it the VIPService is never approved and the hostname never serves.

3. Replace the two `tailscale.com/cap/tsidp` grants with plain network grants (Pocket ID has no `WhoIs` caps):

   ```json
   {"src": ["group:app-users", "group:media-users", "group:home-users", "tag:router", "tag:travel-router"],
    "dst": ["tag:idp"], "ip": ["tcp:443"]},

   {"src": ["tag:k8s-oidc"], "dst": ["tag:idp"], "ip": ["tcp:443"]},
   ```

   `group:admins` is already covered by `{"src": ["group:admins"], "dst": ["*"], "ip": ["*"]}`.

   **`tag:router` is included, which is a change from the first draft of this plan** (2026-10-29). The original only listed `tag:travel-router`, copied from the tsidp grant, whose exclusion of `tag:router` was justified by "`/authorize` rejects tagged sources" — an exemption that no longer exists. Home-LAN clients behind `tag:router` already reach `tag:apps` (`linkding`, `romm`, `donetick`), so without this they would be redirected to the IdP and blocked, losing a login they never had to lose. The `tag:router` test entry therefore moves `tag:idp:443` from `deny` to `accept`.

   Dropping the caps also drops Immich's `extraClaims: {"isAdmin": true, "immich_role": "admin"}`. Nothing replaces it: the existing admin row in Immich is already `admin`, so the migration is unaffected, but the first *new* SSO user would register as a normal user. If that ever matters, set Immich's own role claim in Administration -> Settings -> OAuth rather than reintroducing a cap.

4. `tests`: rename every `tag:tsidp:443` to `tag:idp:443`, in accepts and denies — except the `tag:router` entry, which flips to `accept` (see step 3).

5. Delete the comment block about caps resolving through `WhoIs`; note instead that Pocket ID needs plain reachability only.

Not a policy change but worth recording: tagged sources now work. `tag:dev`, home-router LAN clients (`tag:router`) and travel-router LAN clients can complete a browser login, which tsidp refused with `tagged node doesn't have a user identity`.

The policy and the old device must not cross: `tag:tsidp` leaves `tagOwners` in this change, so the policy only makes sense once the `idp` device is deleted. That is why the PR opens first (CI runs `action: test`) and merges only after the device is gone.

Deployment notes:

- `strategy: Recreate` (RWO PVC), container `app`, container port `http` 1411.
- PVC `data`, 1Gi, `zfs-generic-nvmeof-csi`, mounted at `/app/data`. ZFS zvol + a normal filesystem, so Pocket ID's "no SQLite on a network share" warning does not apply.
- Service port 80 -> `http`; probes `GET /healthz` on `http`.
- Ingress: `ingressClassName: tailscale`, `tailscale.com/proxy-group: ingress-proxy-group`, `tailscale.com/tags: tag:idp`, `tls.hosts: [idp]` (this is what creates `idp.beaver-cloud.ts.net`, exactly like `linkding`).
- `components/app-pod-hardening` + `components/app-tmp-dirs` as usual: the distroless image runs as an arbitrary uid, and with `fsGroup: 1000` the empty PVC is writable at `/app/data`. Pocket ID writes nothing outside it (hence the explicit `DB_CONNECTION_STRING` / `UPLOAD_PATH`, since the image's default relative `data/...` paths assume a writable `/app`).
- requests/limits 128M/256M; raise the limit if it OOMs during passkey setup (Pocket ID is a Go binary with an embedded frontend, it is not memory-hungry).

## Phase 4 - clients and secrets

Pocket ID has no DCR: each app needs its client before it can log in. Create the 6 clients and let the *script* choose the secrets (`AUTO_CREATE_OIDC_CLIENT_SECRET=false` means Pocket ID will not also mint one). Run this from the workstation; `STATIC_API_KEY` stays in the cluster secret.

```sh
API=https://idp.beaver-cloud.ts.net
K=$(kubectl -n pocket-id get secret pocket-id-secret -o jsonpath='{.data.STATIC_API_KEY}' | base64 -d)

mk() { # id name callback-json
  curl -fsS -X POST "$API/api/oidc/clients" \
    -H "X-API-KEY: $K" -H 'content-type: application/json' \
    -d "$(jq -n --arg id "$1" --arg n "$2" --argjson cb "$3" \
      '{id:$id,name:$n,isPublic:false,skipConsent:true,callbackURLs:$cb}')" > /dev/null
  s=$(openssl rand -hex 32)
  curl -fsS -X POST "$API/api/oidc/clients/$1/secrets" \
    -H "X-API-KEY: $K" -H 'content-type: application/json' \
    -d "$(jq -n --arg s "$s" '{secret:$s}')" > /dev/null
  printf '%s\t%s\n' "$1" "$s"
}

mk linkding  Linkding  '["https://linkding.beaver-cloud.ts.net/oidc/callback/"]'   > /tmp/opencode/linkding.cred
mk miniflux  Miniflux  '["https://miniflux.beaver-cloud.ts.net/oauth2/oidc/callback"]' > /tmp/opencode/miniflux.cred
mk romm      RomM      '["https://romm.beaver-cloud.ts.net/api/oauth/openid"]'     > /tmp/opencode/romm.cred
mk donetick  DoneTick  '["https://donetick.beaver-cloud.ts.net/auth/oauth2"]'      > /tmp/opencode/donetick.cred
mk semaphore Semaphore '["https://semaphore.beaver-cloud.ts.net/api/auth/oidc/pocketid/redirect"]' > /tmp/opencode/semaphore.cred
mk immich    Immich    '["https://immich.beaver-cloud.ts.net/auth/login","https://immich.beaver-cloud.ts.net/user-settings","https://immich.beaver-cloud.ts.net/api/oauth/mobile-redirect","app.immich:///oauth-callback"]' > /tmp/opencode/immich.cred
```

Then, per client, set **Access -> Allowed user groups** (a new client lets nobody in until this is done; `skipConsent` only removes the consent screen).

Re-sealing a multi-key secret without touching plaintext on disk:

```sh
kubectl -n romm get secret romm-secret -o yaml \
  | yq 'del(.metadata.ownerReferences, .metadata.uid, .metadata.resourceVersion,
            .metadata.creationTimestamp, .metadata.managedFields,
            .metadata.labels, .metadata.annotations)
        | .data.OIDC_CLIENT_SECRET = "'"$(printf %s "$NEWSECRET" | base64 -w0)"'"' \
  | kubeseal --controller-namespace kube-system --controller-name sealed-secrets-controller -o yaml \
  > apps/romm/secret-sealed-secret.yml
```

## Phase 6 - relink and re-address accounts

Do this after the app pods roll with the new client credentials and **before** anyone logs in. Pocket ID's `sub` is the user's UUID (`backend/internal/service/jwt_service.go`: `.Subject(userID)`), and it cannot be made to equal the old `userid:63232476793795202` (`UserCreateDto.ID` is `binding:"uuid"`), so every app that stores the subject needs it updated. Taking the opportunity to move the address means the email changes too.

`<uuid>` = the Pocket ID user id (`GET /api/users` with the static key, or the client's *OIDC Data Preview* in the admin UI).

```sql
-- linkding (sqlite, PVC is writable; python3 is in the image)
-- matched by email, so this alone is what stops a duplicate account
UPDATE auth_user SET email='kevindurb@fastmail.com' WHERE username='kevindurb';

-- miniflux (postgres, matched on openid_connect_id only; username stays)
UPDATE users SET openid_connect_id='<uuid>' WHERE username='kevindurb';

-- romm (mariadb); oidc_issuer stays https://idp.beaver-cloud.ts.net
UPDATE users SET email='kevindurb@fastmail.com', oidc_sub='<uuid>' WHERE username='kevindurb';

-- immich (postgres)
UPDATE "user" SET email='kevindurb@fastmail.com', "oauthId"='<uuid>' WHERE name='Kevin Durbin';
```

```sh
kubectl -n linkding exec deploy/linkding-app-deployment -- python3 -c \
  "import sqlite3;c=sqlite3.connect('/etc/linkding/data/db.sqlite3');c.execute(\"UPDATE auth_user SET email='kevindurb@fastmail.com' WHERE username='kevindurb'\");c.commit()"
kubectl -n miniflux exec deploy/miniflux-postgres-deployment -- psql -U miniflux -d miniflux -c \
  "UPDATE users SET openid_connect_id='<uuid>' WHERE username='kevindurb'"
kubectl -n romm exec deploy/romm-mariadb-deployment -- sh -c \
  "mariadb -uroot -p\"\$MARIADB_ROOT_PASSWORD\" romm -e \"UPDATE users SET email='kevindurb@fastmail.com', oidc_sub='<uuid>' WHERE username='kevindurb'\""
kubectl -n immich exec deploy/immich-postgres-deployment -c postgres -- psql -U immich -d immich -c \
  "UPDATE \"user\" SET email='kevindurb@fastmail.com', \"oauthId\"='<uuid>' WHERE name='Kevin Durbin'"
```

donetick and semaphore have neither `sqlite3` nor Python in their images (linkding does), so scale them to 0 and mount the PVC in a throwaway pod:


## Risks

- **One-way.** `tsidp-data` (signing key, DCR clients) and the `idp` device are deleted. Restoring tsidp means a fresh interactive tsnet login plus re-registering every client.
- **Name conflict is the only hard blocker.** If the operator will not provision the `idp` VIPService, the `idp` device still exists.
- **Address mismatch = duplicate accounts.** linkding, donetick and semaphore match on email/username; romm/immich/miniflux match on `sub`. Both must be corrected before the first post-migration login, and Phase 6 must therefore run inside the same window, before verification.
- **`/setup` is open until the first user exists.** Reachable by `group:app-users`, `group:media-users`, `group:home-users`, `tag:travel-router` and admins. Create the admin user immediately; optionally keep the idp grant admin-only for the window.
- **Lockout.** A single admin account protected only by passkeys. Register two passkeys on separate devices, back up the sealed `ENCRYPTION_KEY` (the sealing key does not protect Pocket ID's data), and note that the admin-issued login code needs a *logged-in* admin, so a second admin account kept for break-glass is the only real fallback.
- **`prune: false`.** Dropping `platform/tsidp/app.yml` leaves the `tsidp` Argo Application behind; delete it manually (Phase 3).
- **Secret-less clients.** `AUTO_CREATE_OIDC_CLIENT_SECRET=false` means a client created without the script has no secret and fails at the token exchange. Check each client's Credentials tab.
- **`externalName` drift** (unchanged): the operator rewrites the `idp` Service; `infrastructure/tailscale/app.yml` keeps the `ignoreDifferences` entry. If the Service is renamed, update it.
- **Stale gatus ConfigMaps** (`prune: false`): deleting the `tsidp` namespace removes its old check; if Pocket ID's gatus config is later edited, delete the superseded hashed ConfigMap.
- **SQLite edits need downtime** for donetick and semaphore (scale to 0, copy, edit, copy back) — do not copy a live WAL-mode database.
- **`UI_CONFIG_DISABLED=true`** moves every application setting to env. If a setting is only available in the UI, either add its env var or drop the flag and configure it there.
